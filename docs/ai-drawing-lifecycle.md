# AI 绘图与编辑器生命周期

`drawing_draw` 在主进程生成骨架，通过画布握手交给 Excalidraw 转换、追加和保存。
只有真正创建 API 并结束 `isLoading` 后，渲染端才发送 `canvasReady`。
工具成功回执必须等待保存成功，保存 IPC 返回失败时不能报告完成。

场景刷新使用现有 API 更新，不能因保存广播重新挂载编辑器。旧 React root
只能卸载自己拥有的子节点，不能在延迟清理时清空新画布。自动保存定时器在
卸载、外部刷新及 AI 应用前取消。AI 保存期间返回的旧读取结果不得覆盖正在
应用的内容。切换绘图时，上一张绘图尚未完成的读取也不得写入新场景。

每次追加都会检查元素 ID 冲突，同时重映射箭头端点，避免多批次使用相同 ID。
语义节点 `cylinder` 兼容映射成 `rectangle`：Excalidraw 没有原生圆柱体类型，
直接传入会在连线绑定时触发 undefined.id。其他未知节点类型在布局阶段明确
拒绝；渲染端也验证骨架类型、唯一 ID 和连线端点，再调用官方转换器。
Excalidraw 0.18 的 `captureUpdate` 位于 `updateScene` 的唯一参数对象中。
磁盘场景不保存弹窗、文字编辑、选择及指针交互状态。绘图保存快捷键仅在画布
内部生效，编辑器不启用全局键盘处理，也不在挂载时自动抢焦点。

## 验证记录（2026-10-15）

使用独立临时用户目录和本地 OpenAI 兼容流式测试端点驱动真实 Electron 界面，
未使用用户模型密钥或修改用户任务。

- 修复前首次新建画布返回“画布尚未就绪”；修复后返回 `created: true`。
- 实际保存两个形状、两段文字及一条连线，共 5 个 Excalidraw 元素。
- 连续追加后保存 10 个元素，全部 ID 唯一；修复前旧场景刷新会恢复为 5 个。
- 绘图后通过键盘向 AI 输入框和全局搜索输入框输入文本成功，页面未观察到
  JavaScript 异常；重新加载页面后仍保存 10 个唯一元素。
- 单元测试覆盖延迟就绪、刷新不重挂载、外部输入焦点、快捷键范围、保存期间
  的旧场景竞争、ID 与绑定重映射、临时状态过滤和保存失败。

尚未稳定复现用户报告的“所有输入框失效”；此次修复消除了已确认的编辑器
重挂载和全局保存快捷键问题。真实远程模型是否选择工具属于另一层行为，
本轮本地端点测试验证的是工具调用到画布及文件的完整执行链路。

用户提供的九节点架构图另作为 `tests/fixtures/drawing-architecture.json`
回归输入。真实转换器修复前复现 undefined.id；修复后得到 9 个节点、8 条箭头
和 17 段文字（共 34 个元素），并成功保存到原先空白的绘图中。

## 整图覆盖与 Loading scene

`drawing_save` 的 scene 参数使用序列化 JSON 字符串，避免 XML 工具调用把
数组改写为 `{ item: ... }`、把数字及布尔值变成字符串。运行时同时兼容已经
解析的 JSON 对象，但所有保存入口均先执行 `assertDrawingScene`，在改名和
文件覆盖前拒绝非法结构。渲染端读取后也校验，错误显示为加载失败提示，
不把已知损坏结构送入 Excalidraw 初始化。

实测用户调整认证连线后写回的场景存在上述数组包装问题。先备份原始 JSON，
再修复字段类型与数组，保留 34 个元素和认证节点/连线的位置修改；重新加载
后 Loading scene 消失。此类历史数据修复针对已确认的输入进行，不自动猜测
无法解释的数据。
