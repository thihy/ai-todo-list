# Design

## Native action bridge
Inventory the installed 0.18.1 ActionName union and actual runtime registry. Add a narrowly scoped, fail-fast build transform to expose registry inspection and awaited native action execution through the existing imperative API; use official action.perform and syncActionResult rather than imitating actions or raw scene replacement. Verify development and production bundles. Report registry/predicate availability, input guidance and prerequisites to the model. Expose every registered action, including UI/clipboard/export actions; actions requiring human interaction open their normal UI and report that fact, never fabricate durable success. Revision checks and deduplication apply to execution; read-only policy denies state-changing actions. Save actual scene read-back when changed, retain a bounded checkpoint, and preserve pending manual saves on rejected actions. Test against the complete registry and maintain per-action evidence.

## Semantic text compatibility and tool removal
Accept containerId only for added text and verify a real, unlocked, supported container without an existing label; use native binding conversion. Alignment properties are typed enums applied to real text through native layout. Unknown internal fields remain rejected. Remove drawing_read registration and all model-facing references, while retaining historical UI labels where needed. Drawing failures stay recoverable through correct engine operations, never filesystem/JSON fallback.

## Annotation UX
Reuse the existing neutral surface, borders and teal primary action. A compact input follows the live selected bounds inside the canvas, clamped to its viewport and away from the top toolbar. No forced focus on selection. Enter saves an annotation; Shift+Enter inserts a line; Escape closes the editor. Each annotation stores actual drawing/element IDs and a scene revision, plus the literal user's instruction. A collapsible pending panel shows numbered items, editable text, target highlight and delete. One primary submit combines them into an ordinary chat message; stale/deleted references are revalidated, failed submission preserves drafts, and busy AI uses the existing message queue. No annotation is silently written into the drawing or creates a task. Support narrow windows and keyboard focus, input labels and polite status announcements. Persist drafts per drawing locally so tab switches do not lose work.

## Compact progress
Use a dedicated editor BrowserWindow positioned beside the floating todo window and clamped to the display work area, minimum usable size and full opacity. Keep the original floating window size/list intact. Editor provides task title, progress percentage and note, explicit save/cancel, keyboard escape and inline error. Validate actual task ID in main, reuse progress.log and existing data-change broadcasts; close never commits.

## Verification
Unit tests for schema/binding invariants, build transform coverage and all native action names, annotation prompt and submission isolation, progress window geometry/lifecycle. Actual Electron tests cover representative native action families plus an exhaustive action registry traversal with appropriate fixtures/prerequisites and honest per-action outcomes, batch annotation dispatch while assistant collapsed/busy, draft recovery, save/reopen and compact editor at minimum floating size. Run typecheck, appropriate unit suite, build, strict specs and packaged smoke after closing the user's running app before rebuilding.

## Verified implementation details
Native style/alignment edits wait for the requested React selection to commit and restore the prior user selection when the user has not selected something else. Annotation typing pins its target IDs until the user interacts with the canvas again, so concurrent AI edits do not redirect an unfinished instruction. The native paste callback is wrapped by upstream withBatchedUpdates, which discards its promise; the bridge tracks and awaits the inner paste task and image initialization explicitly. Clipboard cut awaits copy success before deleting anything. FileSystem handles and collaborator following objects remain transient and are excluded from drawing persistence. Full registry coverage and isolated clipboard/image/failure evidence are recorded in docs/ai-drawing-action-coverage.md.
